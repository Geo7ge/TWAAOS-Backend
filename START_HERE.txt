💾 MIGRAȚII DATABASE:
═══════════════════════════════════════════════════════════════════════════════

Migrațiile sunt AUTOMATE - se rulează la startup din:

  Backend/supabase/migrations/

Fiecare fișier .sql din director este executat în ordine alfabetică.

Adăugare migrație NOUĂ:

  1. Creează fișier:
     Backend/supabase/migrations/20260618_create_new_table.sql
  
  2. Adaugă SQL:
     CREATE TABLE new_table (
       id SERIAL PRIMARY KEY,
       name VARCHAR(255),
       created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
     );
  
  3. Restart database:
     docker-compose restart db
     
     SAU (dacă vrei fresh):
     docker-compose down -v
     docker-compose up -d


🛠️  COMENZI ZILNICE UTILE:
═══════════════════════════════════════════════════════════════════════════════

Pornire:                    docker-compose up -d
Oprire (pastrează date):    docker-compose down
Oprire (șterge date):       docker-compose down -v
Restart:                    docker-compose restart
Status containere:          docker-compose ps
Logs API:                   docker-compose logs -f api
Logs Database:              docker-compose logs -f db
All logs:                   docker-compose logs -f
SQL prompt:                 docker-compose exec db psql -U proiect_user -d proiect_db
Rebuild image:              docker-compose build --no-cache api
Backup DB:                  docker-compose exec db pg_dump -U proiect_user -d proiect_db > backup.sql
Restore DB:                 docker-compose exec -T db psql -U proiect_user -d proiect_db < backup.sql


🐛 TROUBLESHOOTING RAPID:
═══════════════════════════════════════════════════════════════════════════════

PROBLEMĂ: "Port already in use"
SOLUȚIE:  Schimbă în .env.docker:
          DB_PORT=5433
          API_PORT=8001

PROBLEMĂ: "API not responding"
SOLUȚIE:  docker-compose logs api
          (Vede eroarea detaliată)

PROBLEMĂ: "Database connection refused"
SOLUȚIE:  docker-compose ps
          Asteaptă ca proiect_db să fie "healthy"
          Poi restart API: docker-compose restart api

PROBLEMĂ: "Container crăpat după rebuild"
SOLUȚIE:  docker-compose down -v
          docker-compose build --no-cache
          docker-compose up -d

PROBLEMĂ: "Am editat codul și nu se vede"
SOLUȚIE:  docker-compose rebuild --no-cache api
          docker-compose restart api

🎓 CONCEPTE CHEIE EXPLICATE:
═══════════════════════════════════════════════════════════════════════════════

Docker:
  Containerizare = Packaging aplicației cu dependențele
  Izolat = Fiecare container are propria versiune
  Portabil = Rulează identic pe orice sistem
  
Docker Compose:
  Orchestrare = Gestiuni multiple containere
  docker-compose.yml = Declarativ: 2 servicii (db, api)
  Networks = Containere pot comunica prin hostname (db)
  Volumes = Persistență date (postgres_data)
  Environment = Variabile injectate în containere

PostgreSQL în Docker:
  Image: postgres:17-alpine (mic, rapid)
  Port: 5432 (standard)
  Migrații: Auto-rulate din docker-entrypoint-initdb.d
  Volume: postgres_data (datele sunt persistent)

FastAPI în Docker:
  Image: Buildat din Dockerfile
  Entrypoint: entrypoint.sh care asteaptă database
  Healthcheck: Verifica DB healthcheck înainte de start
  Reload: --reload permite auto-reload la schimbări (DEV)
